# Landing pages and single-page campaigns

Use for: Product launch, campaign, event presentation, simple one-page portfolio.

## Scope and workflow

Sections, trust evidence, primary CTA, and contact/registration only when requested.

## Module selection

seo; content for editable sections; inquiries for lead capture; bookings for capacity-limited registration.

Resolve these module names through the [module index](../modules.md); load only selected modules and their applicable dependencies. Suggested modules describe requirements, not prebuilt features.

## Admin and boundaries

Ask whether admin is needed unless already answered. A static single page can remain static.

No accounts, cart, payment, inventory, or blog by default. Paid event registration adds bookings/payments from actual requirements.

## Acceptance

CTA -> actual destination or stored submission -> visible result; responsive section navigation and metadata.

Use [Verification](../verification.md) for execution evidence and completion status.
